Test Infrastructure — Implementation Plan (Plan 1 of 4)

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps marked ☐ are checkboxes for tracking. Also load the pip-angular-testing skill before touching any spec.

Goal: Build isolated, deterministic test infrastructure — dedicated emulators, a shared seeded data set, per-area test runs — and finish with the first meaningful e2e run, whose failure list becomes Plan 2.

Architecture: A single source of truth for test ports and a demo-* project ID drives a wrapper around firebase emulators:exec. E2E runs an Angular e2e build configuration against those emulators; Playwright's global setup seeds a declarative, validated data set through the Admin SDK. An area map ties app unit specs, functions specs and Playwright tags together behind pnpm test:area.

Tech stack: Angular 22 (@angular/build:unit-test, Vitest), Playwright 1.64, Firebase CLI emulators, firebase-admin 14, Node 24 (node:test for script tests).

Spec: docs/superpowers/specs/2026-10-19-test-suite-design.html — read it first.

Later plans (written after this one lands): Plan 2 repairs the existing e2e specs from the failure list Task 9 produces; Plan 3 adds e2e coverage for new areas (including stubbing or caching tesseract.js's language-data download for scanReceipt, per spec §3); Plan 4 fills unit-test gaps (app + functions).

Global Constraints

  • Never touch the default emulator ports (4000, 4400, 4500, 5000, 5001, 8080, 9099, 9150, 9199) — the owner's dev emulators, or another project's, may be running there. Every test command in this plan uses the test ports below.
  • Never run pnpm install/pnpm add or any network download; hand those to the owner and wait.
  • Any Admin SDK init sets FIRESTORE_EMULATOR_HOST, FIREBASE_AUTH_EMULATOR_HOST, FIREBASE_STORAGE_EMULATOR_HOST before initializeApp, and refuses to run unless the project ID starts with demo-.
  • Test project ID: demo-pipsplit-test. Storage bucket: demo-pipsplit-test.appspot.com.
  • Test ports: auth 19099, firestore 18080, firestore websocket 19150, storage 19199, functions 15001, hub 14400, logging 14500, UI disabled. E2E dev server: 4300.
  • All seeded email addresses use the reserved .test TLD (@pipsplit.test) so nothing can ever be delivered.
  • No CI changes. e2e/feature-tour/ (screenshot capture) deliberately uses the dev emulators and port 4200 — leave it untouched.
  • App code follows CLAUDE.md conventions (signals, protected readonly inject, no rxjs, pnpm). Commit messages end with [no-deploy] when no app behaviour changes, plus the Co-Authored-By trailer.
  • Never use vi.resetAllMocks(); never waitForTimeout in new e2e code.

Review Focus

  1. Dev emulators running at the same time. A test run while the owner's dev emulators are up on the default ports must leave them untouched. Pinned by Task 1 step "concurrency check" and re-checked in Task 9.
  2. A previous run crashed and left a test port occupied. The wrapper must fail within seconds, naming the busy port and pointing at pnpm kill-test-ports, not hang or half-start. Pinned by Task 1 test findBusyPorts reports a listening port.
  3. Someone runs pnpm exec playwright test directly, without the wrapper. Global setup must fail immediately with "start e2e via pnpm e2e", not time out test by test. Pinned by Task 4 step "unwrapped run".
  4. The functions build is broken or stale. --build-functions must abort before starting emulators and show the tsc errors. Pinned by Task 1 test buildExecPlan puts the functions build first and step "broken build".
  5. The sign-up trigger overwrites seeded profile fields. createUserProfileOnSignUp merges default profile values; a seeded venmoId must survive. Pinned by Task 6 test seeded profile fields survive the sign-up trigger.
