New E2E Coverage — Implementation Plan (Plan 3 of 4)

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps marked ☐ are checkboxes. Load the pip-angular-testing skill first; its "E2E (Playwright)" section is binding (rules, seed data, ownership, signInAs, running, gotchas). Plan 2's lessons are in it.

Goal: Every feature that never had e2e coverage gets tests for its main journeys and the integration points unit tests can't reach (Firestore and Storage round-trips, dialogs, router hand-offs, function calls), on the shared seeded data, passing alone and in parallel.

Architecture: One spec per area under e2e/<area>/, each with its own seeded dataset (owned groups and users) and a page object extending BasePage. The seeder grows to cover memorized expenses, rental details, stored receipts, left and invited members, and the global mail and app_errors collections. Missing data-testids are added to templates. The receipt OCR callable is mocked in the browser. Real Cloud Functions are used everywhere else: invites, linking, admin reports, error logging.

Tech stack: Playwright 1.64, Angular 22 (signal forms, zoneless), Firebase emulators via pnpm e2e / pnpm test:area, the e2e seeder (e2e/seed/).

Spec: docs/superpowers/specs/2026-10-19-test-suite-design.html (§2 goal 2 and anti-goals, §3 email/OCR constraints, §4 data ownership, §5 areas, §6c, §7 done).

Inputs: docs/superpowers/plans/2026-10-19-infra-followups.html (Plan 3 section, folded into Tasks 1 and 12).

Branch: e2e-new-coverage, created from dev.

Global Constraints

  • All rules in the skill's E2E section apply: never clear data; shared is read-only; mutate only data your spec owns; unique runtime names; scope every assertion to your own data; tag every test; isolated emulators only; no waitForTimeout; no mail to shared users.
  • No order dependence: no describe.serial, no state carried between tests, and a multi-step journey is one test. Every spec passes alone, and every single test passes alone (--grep).
  • No conditional assertions: no if (await x.isVisible()) around an expect.
  • Bug triage (spec §2, §6b): if the app looks wrong, keep the assertion of the correct behaviour, mark the test test.fail() with a comment describing the bug, and list it in the task report with evidence. Never change an assertion to match broken behaviour, and never change app logic. Worked numbers in this plan come from reading the code. If the app disagrees, recompute by hand from the cited utility before deciding which side is wrong.
  • App template changes are limited to adding data-testid (and aria-label where a control has no accessible name). Test ids are kebab-case and prefixed by feature when they could repeat across pages (e.g. memorized-create-expense-button). Commits containing only those changes carry [no-deploy]. Run the touched component's unit spec after adding ids.
  • Runtime users: only the invite-registration journey (Task 9) creates an Auth user at runtime, because registering is what it tests. Its email is fixed and seeded as an invited member; emulators start empty every run.
  • Global collections (mail, app_errors) are written by many specs. Assert only on documents your test seeded or caused, found by a unique recipient, subject or component name. Never click Clear Log, select-all or the admin repair buttons.
  • Router-state hand-offs (rental → add, memorized → add, scan → add) survive only in-app navigation. Never page.goto the target page mid-journey.
  • Blur-driven inputs: amount, nights, room and split inputs commit on blur. Page-object fill helpers fill, blur and assert the formatted value (the existing fillCurrency pattern).
  • New seeded emails end in @pipsplit.test. New group names are unique across all datasets and start with the area (e.g. "Rental – Create").
  • Never touch the default emulator ports. No pnpm install/add/downloads. Commit messages end with [no-deploy] (all of Plan 3 is test or testid-only) and the Co-Authored-By trailer.
  • After each task:
    • pnpm test:area <areas touched> passes (unit + functions + e2e);
    • cd e2e && pnpm exec tsc --noEmit -p . is clean;
    • pnpm test:area --check and pnpm test:scripts pass;
    • each new spec file passes when run alone twice (each run starts cold).

Review Focus

  1. Hand-offs lost to a reload: a journey that reaches Add Expense by URL would get a blank form and pass or fail for the wrong reason. Pinned by each hand-off test (Tasks 4, 5, 6) asserting a prefilled value on Add Expense before saving.
  2. Global collections: a mail or error-log assertion that counts rows, or picks the first row, flakes when another worker writes. Pinned by Task 11's rule (rows found by seeded subject or component) and Task 9's mail lookup by recipient. Task 12 adds a grep gate: no Clear Log / select all / repair-button clicks in e2e/.
  3. One-way user state: receiptPolicy, a changed password, an invite cooldown or a saved default group leaking into a second test as the same user. Pinned by the dataset table (one owned user or member per mutating test) and by the "run each spec alone twice" step.
  4. Blur-dependent buttons: Continue/Save/Generate stay disabled until a field blurs, so a test that fills without blurring fails intermittently or for the wrong reason. Pinned by page-object fill helpers that blur and assert the formatted value (Tasks 3, 4, 5).
  5. Data-dependent tour lengths: tours skip steps based on role and data, so a hard-coded step count breaks when data changes. Pinned by Task 10 reading "N of M" from guided-tour-count and walking until "M of M".
