Plan 4 — owner pre-release checklist (in this order)

The branch changes Firestore rules, Cloud Functions and the app together (B1, B12, B13, B14). Do these in order:

  1. Run the email audit (read-only, production): pnpm query audit-invalid-emails. It lists Auth users, users docs and members whose email fails the single-valid-address rule. Those addresses can no longer be changed to another bad value and are skipped by every server email; decide whether any need manual repair.
  2. Dry-run the profile cleanup (production, writes nothing): pnpm query clear-unverified-profile-emails. It sizes the legacy profiles that hold an unverified or foreign address in users/{uid}.email. Do NOT pass --apply yet: before the deploy an old client's session sync rewrites the unverified address on the user's next load and undoes it. The script refuses to start with any *_EMULATOR_HOST set.
  3. Delete the old sendEmail function, because the release workflow deploys functions without --force and would abort on the function that no longer exists in the code: firebase functions:delete sendEmail --region us-central1 --project pip-cost-sharing --force
  4. Release the rules and the app together (push to release; the workflow deploys both). The new rules refuse the old client's profile writes and email changes, so a cached old PWA client will see failures until it reloads; the app is the other half of the same change (sendEmail callers, verifyBeforeUpdateEmail, token-email linking). Two workflow traps: (a) the deploy is skipped if the PR title or description contains [no-deploy] or [skip-deploy] (.github/workflows/firebase-deploy.yml check-skip), and almost every Plan 4 commit message carries [no-deploy], so write the PR description yourself (don't use gh pr create --fill or paste the commit list); (b) the functions and rules change detection diffs HEAD~1..HEAD on release, so merge with a merge commit or a squash, never a rebase merge, or the functions/rules changes can be missed.
  5. Run the cleanup with --apply after the deploy: pnpm query clear-unverified-profile-emails -- --apply (--apply also refuses an implausible batch unless --force-threshold is added; read its output first). Dry-run again a day later; expect zero. Only then run repairOrphanedMembers / link-orphaned-members. The script never unlinks members; it lists suspicious past links for manual review.
