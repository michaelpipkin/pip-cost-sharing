App bugs found during Plan 2

For the owner to decide. App code was not changed (Plan 2 allowed only data-testid additions). A pinned test asserts the correct behaviour and is marked expected-to-fail; it will fail the run once the bug is fixed, which is the cue to remove the marker.

BugEvidencePinned by
Deep-link redirect race. Reloading (or bookmarking) an authenticated deep link such as /expenses/add or /analysis/summary right after sign-in, on a cold load, can land on /expenses. GroupService.handleGroupsSnapshot decides whether to redirect from router.url, which stays '/' until the initial navigation commits (after the lazy loadChildren, the async authGuard and loadComponent). When the groups snapshot arrives first, the in-flight deep link is replaced by /expenses. Found by the expenses spec in Task 5; confirmed against the router source in review. Task 8 measured it: 7 of 237 full loads of /administration/groups by a signed-in user landed on /expenses, every one with timing data during a ~10 s page-load stall (the stall delays the initial navigation past the groups snapshot). It also broke one pnpm test:area groups run before GroupsPage.goto went in-app. Any full load of a deep link is exposed, reloads included. it.fails('KNOWN BUG: does not redirect a deep link whose initial navigation is still pending') in src/app/services/group.service.spec.ts (deterministic unit pin; an e2e test.fail() would flake). The e2e suite works around it by navigating in-app after sign-in.
History detail money format. The payment detail page shows "$25.00" where History, Summary and the copied text show "$ 25.00"; a non-USD group would get Angular's default USD symbol. history-detail.component.ts:1 imports CurrencyPipe from @angular/common instead of @shared/pipes/currency.pipe. Every full run in Task 8: getByTestId('payment-total') expected "Amount: $ 25.00", received "Amount: $25.00". Fixed (branch group-currency-pipe). Now asserted for real by "should display payment history and its detail" in e2e/critical-flows/history.spec.ts, plus a unit test in history-detail.component.spec.ts.
Same pipe in rental: rental-grid.component.ts:1 and rental-edit-dialog.component.ts:1 also imported Angular's CurrencyPipe (templates use | currency). Import lines; no e2e coverage of the rental screens yet. Fixed with the history detail. Checked by rental-edit-dialog.component.spec.ts (a euro group's total and grid amounts).
Unconditional defaultGroupRef write. Every app load and every groups snapshot rewrites users/{uid}.defaultGroupRef, even when it is unchanged, and each write also fires the syncUserEmailLower trigger (onDocumentWritten('users/{userId}')). GroupService.getGroup calls setDoc(userRef, { defaultGroupRef: groupRef }, { merge: true }) on every call (group.service.ts ~line 372), reached from autoSelectGroup. In tests this made "shared is read-only" impossible to hold literally; the shared users are seeded with the value the app writes. Not pinned (a skip-if-unchanged fix is the owner's call; it would save one write plus one trigger per load in production).
Group switch undone by auto-select. A group switch made right after sign-in can be reverted by the default-group auto-select still in flight, and two tabs signed in as the same user overwrite each other's selection. Seen as a 1-in-2 flake in groups-admin ("create, select and rename a group") when two parallel tests shared a user. Fixed test-side with one owned user per test that selects groups. Not pinned (timing-dependent).
Stale stores after a switch. After switching groups, the previous group's members and categories stay in the stores until the new group's data arrives, so a fast reader can see the old group's lists. Reported during the expenses repair (Task 5) from the store code path; not reproduced in isolation. Page objects wait for the new group's content. Not pinned.
Inert defaultButton attribute. 12 templates (e.g. add-expense, add-category, edit-category) put a defaultButton attribute on a button, but no directive matches it, so it does nothing. grep -rn defaultButton src/app --include=*.ts finds no selector. Not pinned (no behaviour to test; remove it or add the directive).

Machine-stall probe recipe

Used to measure the 10-12.5 s stalls that justify the config-level 15 s expect timeout. Re-run it if waits start failing at about 15 s instead of nudging timeouts. A throwaway spec (not committed) that, per iteration: loads /auth/login, signs in as a seeded user with signInAs, then does a full page.goto of a deep link (e.g. /analysis/summary). Record, with Date.now() deltas, the duration of each step (DOMContentLoaded, sign-in landing, route render, the data load behind the loading overlay) and the final page.url() (a landing on /expenses is the deep-link redirect race). Run it with pnpm e2e <probe file> --repeat-each 80 --workers 2 and tally steps over about 5 s and the landing URLs. The last measurement: 42 of 80 iterations had one step stalled by a near-constant extra 10 s (worst 12.5 s on an expect), the rest settled in about 1.5 s, and 7 of 237 deep-link loads redirected to /expenses.
